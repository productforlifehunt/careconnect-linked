# 20. 设置汇总（Settings summary）

## 原则（Rules）

1. 一切设置的**读取与写入**都调用 `src/lib/ai-dynamic-knowledge.ts` 内的 skill，读与写写在**同一条 skill** 里。
2. 前端文件只是渲染框架：不储存数据结构、不储存读写方式、不储存 CCT / column。
3. 无论是否 AI 调用，都用 **skill 名** 定位：`runSettingSkill(name, value)` / `readSettingSkill(name, snapshot)` / `loadSettingSkill(name)`。
4. 子 App 差异（不同 column、不同 CCT、不同存储位置）写在**同一条 skill 内**，由 `currentAppScope()` 判定；`perApp` 字段写明差异。
5. `currentAppScope()` 通过 URL 参数 `?__site=`（预览/测试）与上线后真实域名判定；只允许 `challenged` / `carecnc` / `notchsafety`。
6. Edge / 服务端调用必须显式带 App 名：`runSettingSkill(name, value, { app: "challenged" })`，经 `appScopeFromEdge()` 校验，不认识的 App 名**直接报错**，不静默默认。
7. 写入前统一经 `validateSettingWrite()`：未知 skill 名、类型不符、非法选项、非法时间、关闭 locked 安全项 —— 全部拒绝，绝不半写入。

## AI 悬浮对话框（同一条 skill）

- AI 只能从 `SETTING_SKILL_NAMES`（由登记表生成）里选 skill 名，并给出允许值；名字拼错或值非法在 `validateSettingWrite()` 阶段被拒绝，不可能落库。
- 当前值与允许值由 `resolveSettingFacts()` 从同一登记表生成，交给模型阅读；模型不接触 CCT、column、App 值。
- 确认 / 跳过按钮是前端 UI（`src/components/ai/AICompanionChat.tsx`），确认后调用的仍是同一条 skill。
